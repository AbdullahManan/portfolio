Sales Invoice Management System

A full-stack ASP.NET Core MVC application for managing product inventory, sales invoicing, and business reporting — built end-to-end during my internship.

ASP.NET Core MVC EF Core SQL Server ASP.NET Core Identity AdminLTE 4
01 overview

Built during my internship to manage product inventory, sales invoicing, and reporting for a small-business workflow. The system handles the full cycle — from stock tracking and invoice creation to role-based staff access and printable reports — replacing what would otherwise be a manual, spreadsheet-driven process with a structured, auditable web application.

03 key features
  • Role-based authentication (Admin / SalesRep) via ASP.NET Core Identity
  • Real-time stock validation during invoice creation
  • Dynamic multi-line invoice entry with live total calculation
  • Sales & Product reports with multiple filter modes — date range, month, year, by-product
  • PDF export via browser print, with a dedicated 80mm thermal receipt layout
  • Admin-only user management with password reset
04 technical highlights

Runtime stock availability. Rather than storing a mutable "remaining stock" field, available quantity is computed on the fly as opening stock minus the sum of quantities already committed across invoice line items — preventing overselling even when multiple invoices reference the same product concurrently.

Cross-row stock sync. When a product is added to more than one line item in the same invoice, the UI recalculates and caps available quantity live across all matching rows — not just the row being edited — so a user can't accidentally oversell a product within a single invoice.

Print-safe layout isolation. Report and receipt views use a dedicated print layout with scoped @@media print rules, resolving CSS specificity conflicts between the admin theme and the print output so the printed document stays clean regardless of the active dashboard styling.

Save-then-print flow. Invoice creation uses an AJAX save step before triggering the print dialog, ensuring the invoice is persisted and assigned a real ID before a receipt is generated — avoiding orphaned print-outs for invoices that failed validation.
